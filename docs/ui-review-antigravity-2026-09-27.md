## 一、 审查综述与整体体验评价

当前分支在经历上一轮大规模重构后，前端的工程健壮性与可用性相比初始版本有了质的飞跃：
1. **核心痛点已彻底解决**：独立“我的上一掷”与具体六档奖品明细在他人投掷后不会被冲刷覆盖；服务端控制的结果展示阶段（默认 1 秒）有效阻断了快节奏下的状态撕裂；
2. **多端响应式架构完整**：从 320px 窄屏、375px 标准移动屏到 768px 平板与 1440px 桌面宽屏，均实现了无水平横向溢出，桌面端三栏（280/560/312）各司其职；
3. **状态收纳与交互边界清晰**：局内次要操作优雅收敛于“更多”面板；大厅公开房加入/只读旁观与凭码直达分工明确；底部抽屉的单主按钮接管机制杜绝了 DOM 冲突。

但在深入对比实际截图（如 `60-experience-standard-375.png`、`61-experience-12players-320.png`、`65-experience-recent10-375.png` 等）与对应 TSX/CSS 代码后，从专业 UX 与设计工程角度，依然存在若干**信息层级过密、长文本截断策略生硬、首屏垂直空间浪费以及操作手感待精细化**的问题点。

### 建议 1【可确认问题 · 高优先级 · 工作量：小】
### 移动端隐藏骰碗卡片底部的 `.game-hint-note`，释放关键首屏空间并消除底栏粘连风险

- **问题性质**：可确认问题（Definite Layout & Information Redundancy）
- **页面与证据**：
  - **截图证据**：`docs/screenshots/60-experience-standard-375.png`（375×812 标准对局）。OCR 与几何度量显示，卡片底部文本 `本次结果展示中（停留1秒），展示结束后自动开放下一...` 的底部坐标位于 692px+，距离起始于 701px 的悬浮底栏（`.action-bar`）净空不足 10px。
  - **源码证据**：[src/components/GameBoard.tsx](file:///Users/linus/CODE/bobing/src/components/GameBoard.tsx#L189-L208) 中 `{!canRoll ? <p className="game-hint-note">...</p> : null}` 在移动端并未随内联按钮隐藏；[src/styles.css](file:///Users/linus/CODE/bobing/src/styles.css#L2834-L2839) 仅声明基础字体与颜色，未作移动端响应式处理。
  - **信息冗余证据**：在同一个 375×812 移动视口内，“本次结果展示中”同时出现在：
    1. 顶部轮次条（`turn-bar`）右侧倒计时位置；
    2. 轮次条玩家姓名旁的金色标签（`tag-presenting`）；
    3. 骰碗上方的主提示文案（`game-turn-hint`）；
    4. 底部悬浮栏禁用态主按钮（`[掷出好运]`）及描述。
- **对玩家的具体影响**：
  卡片底部的 36 字冗余解释既无法带来增量信息，又白白占用了约 35–45px 的宝贵纵向高度。在稍大字号或长昵称对局中，极易导致主卡片内容被固定底栏部分遮盖，产生截断感和视觉压迫。
- **可实施改法**：
  在移动端媒体查询（`@media (max-width: 900px)`）中增加样式规则：
  ```css
  .game-center .game-hint-note {
    display: none !important;
  }
  ```
  桌面端仍保留该辅助提示（跟在内联掷骰按钮下方），移动端则完全依托顶部轮次条与底栏按钮反馈。
- **优先级与工作量**：**高优先级** / **工作量：小**（仅需 3 行 CSS）。

### 建议 2【可确认问题 · 高优先级 · 工作量：小】
### 移动端席位条（SeatStrip）头像昵称截断策略优化：避免多人长昵称盲区

- **问题性质**：可确认问题（Legibility / Multi-user Identification Defect）
- **页面与证据**：
  - **截图证据**：`docs/screenshots/61-experience-12players-320.png`（320px）与 `docs/screenshots/62-experience-12players-375.png`（375px）。
  - **实际现象**：OCR 与像素核验显示，席位条头像下方的 12 位玩家昵称全部被截断为完全相同的 `团圆长昵…` 或 `团团圆长昵…`。
  - **源码证据**：[src/styles.css](file:///Users/linus/CODE/bobing/src/styles.css#L2685-L2720) 中 `.seat-name` 采用了定宽配合 `white-space: nowrap; overflow: hidden; text-overflow: ellipsis;`。当玩家昵称拥有相同前缀（如“团圆长昵称玩家01”、“团圆长昵称玩家02”或家庭群常见的“老李家大宝”、“老李家二宝”）时，后缀数字被整齐截掉。
- **对玩家的具体影响**：
  席位条本来旨在让玩家“一眼看清牌桌座次和当前是谁”。但长昵称统一截断为前缀后，玩家看着一排一模一样的字样，根本分不清骰子图标落在哪位具体玩家头上，席位条丧失了关键辨识功能。
- **可实施改法**：
  1. **首尾截断优化**：在 CSS/TSX 中对 `.seat-name` 采用智能显示，当长度 >5 字符时，截取前 2 字 + `…` + 后 2 字（例如 `团圆…01`、`团圆…02`），确保末位最具区分度的标识永不丢失；
  2. **触摸轻量反馈**：轻按头像项可弹出原生 `title` 或微型 Tooltip 展示全名，提升可辨识度。
- **优先级与工作量**：**高优先级** / **工作量：小**（仅需优化 `SeatStrip.tsx` 的昵称格式化或 CSS 宽度策略）。

### 建议 3【设计偏好 / 体验优化 · 中优先级 · 工作量：小】
### 卡片内“本次结果”与“我的上一掷”强化视觉层级锚点，消除本人投掷后的瞬时视觉重复

- **问题性质**：设计偏好 / 体验优化（Visual Hierarchy & Cognitive Load）
- **页面与证据**：
  - **截图证据**：`docs/screenshots/60-experience-standard-375.png`。
  - **实际现象**：在本人刚投掷完毕后，骰碗下方的浅金/微红大结果框显示：
    `本次：阿月（我）  博得一秀 · 获得1份`
    紧随其下方的白色内联条（MyRewards inline）显示：
    `我的上一掷：一秀 · 获得1份    我已获1份  我的奖品 ＞`
  - **源码证据**：[src/components/GameBoard.tsx](file:///Users/linus/CODE/bobing/src/components/GameBoard.tsx#L173-L188)。
- **对玩家的具体影响**：
  两个视觉块垂直紧贴，且展示的奖级与份数完全相同。玩家视线扫过时，会产生轻微的困惑：“这是两条不同记录，还是同一条写了两次？”当下一位玩家出手后，上方变为别人的结果，下方才真正体现出“保留自己上一掷”的价值。在本人出手当下，两者的角色定义缺少清晰的心理边界。
- **可实施改法**：
  1. 为上方“本次结果”明确赋予“全桌动态”语意（例如左上角增加微型标签 `[全桌最新]` 或当前出手广播态）；
  2. 下方的“我的上一掷”背景可采用略微区分的独立卡片样式，并增加小徽章图标（如印章质感的 `[个人存盘]` 或固定标题 `【我的战绩】`），使“全桌实时事件”与“个人专属看板”在空间上有明确的逻辑归属感。
- **优先级与工作量**：**中优先级** / **工作量：小**（调整组件少量文案与背景边框样式）。

### 建议 4【设计偏好 / 体验优化 · 中优先级 · 工作量：中】
### “我的奖品”弹窗重构信息次序：六档明细置顶，状元规则长文收纳折叠

- **问题性质**：设计偏好 / 交互优化（Information Architecture in Dialog）
- **页面与证据**：
  - **截图证据**：`docs/screenshots/66-experience-my-prizes-375.png`（375×812 下点击“我的奖品 ＞”后的弹窗）。
  - **实际现象**：OCR 与几何实测表明，从首屏 y=0.190 一路向下延伸至 y=0.550（超过 35% 视高），全部被“我的上一掷”详情以及“个人状元经历”中的大段未登顶说明文案所占据（“本局尚未掷出状元牌型，继续投掷冲击状元。本局状元奖品：……x1（全部归最终状元）”）。核心的六档具体奖品明细（状元、对堂、三红、四进、二举、一秀）被推到屏幕最下半截，三红以下必须滑动才能看到。
  - **源码证据**：[src/components/MyRewards.tsx](file:///Users/linus/CODE/bobing/src/components/MyRewards.tsx)。
- **对玩家的具体影响**：
  当玩家在战局中点击“我的奖品”入口时，其第一心理诉求通常是：“我刚才到底拿了什么？六档里我还差哪些？”然而弹窗首屏却先迎面扑来长篇的状元机制解释，真正关心的战利品盘点清单却被挤在折叠线下。
- **可实施改法**：
  1. 将“我的奖品明细”（六档获得数量与奖品名）提升至弹窗首位，采用紧凑清晰的 6 档列表；
  2. “个人状元经历”简化为单行徽章（如“状元：未登顶”或“登顶 1 次（已顶替）”），点击后可展开长段规则说明与状元奖品归属解释；
  3. 让玩家“开窗 1 秒看清所有战利品”，大幅减少弹窗内的滚动成本。
- **优先级与工作量**：**中优先级** / **工作量：中**（重排 `MyRewards.tsx` 弹窗版块顺序与样式）。

### 建议 5【可确认问题 / 交互细节 · 中优先级 · 工作量：小】
### 房间设置（RoomSettingsDialog）精简说明文本，并为结果停留秒数提供 Stepper 步进调节

- **问题性质**：可确认问题 / 移动端表单体验（Form UX & Repetitive Copy）
- **页面与证据**：
  - **截图证据**：`docs/screenshots/67-experience-room-settings-375.png`。
  - **实际现象**：整个设置弹窗一共仅有 3 个有效配置项（大厅公开/仅邀请、允许旁观、结果停留秒数）。然而界面中出现了两段高度冗余的说明文字：
    - 弹窗顶部：4 行大段总述（“结果停留时长可设 0-10秒整数（默认 1秒……）”）；
    - 秒数控件右侧：又出现一段 3 行重复说明（“支持0-10秒整数（默认 1秒……）”）。
    静态文字占去弹窗近 30% 纵向面积；且结果停留秒数目前仅为原生数字输入框。
  - **源码证据**：`src/components/RoomSettingsDialog.tsx` 与 `src/components/RoomSettingsFields.tsx`。
- **对玩家的具体影响**：
  1. 房主在局内打开设置时，界面显得文案密密麻麻、视觉噪音大；
  2. 针对 0–10 整数秒这种极小离散范围的微调，移动端用户点击输入框会唤起系统全键盘，不仅遮挡底部的“保存设置”按钮，更需要“删除旧数字-输入新数字-收起键盘”三步操作，极其繁琐。
- **可实施改法**：
  1. 删减顶部的长篇总述，仅在秒数控件旁保留单行清爽提示；
  2. 在输入框两侧配备大触控区域（宽度 ≥44px）的 `[-]` 与 `[+]` 步进按钮，支持房主单手拇指轻点即可在 0 到 10 秒之间递增递减，完全无需唤起键盘。
- **优先级与工作量**：**中优先级** / **工作量：小**（增设 Stepper 按钮并提炼文案）。

## 三、 第一批实施推荐（Top 3）

若后续排期实施优化，强烈建议按以下最高性价比组合切入：

1. **Top 1：移除移动端骰碗卡片底部的 `.game-hint-note`（建议 1）**
   - **理由**：仅改动几行 CSS，没有任何业务逻辑风险，能够立即为 375px/320px 移动端首屏解脱 40px+ 纵向预算，彻底根治与底部悬浮栏的视觉粘连风险，投入产出比最高。
2. **Top 2：移动端席位条长昵称首尾截断优化（建议 2）**
   - **理由**：直接修复 12 人对局中“全员同名化（团圆长昵…）”的可用性硬缺陷，让常驻席位条真正发挥指示“当前该谁掷”的核心职能。
3. **Top 3：房间设置弹窗文案精简与 Stepper 步进调节（建议 5）**
   - **理由**：直接提升房主局内修改节奏的操作手感，消灭移动端反复弹出/收起系统软键盘的笨拙感，增强功能专业度。

## 四、 现有版本中表现出色、值得严格保留的设计亮点

在审查过程中，我们特别注意到本轮重构中许多极为出色、应予充分保护的优秀实践：

1. **纯数字 6 位房间码与自动前导零处理**：
   从过去的英数混杂升级为纯数字码（如 `028416`），移动端一键调起数字九宫格键盘，粘贴体验顺滑；同时底层完整保留了前导零与旧字母码兼容，极为周全。
2. **悬浮底栏与半屏抽屉的主按钮单例接管机制**：
   移动端在收起抽屉时底栏显示“掷出好运”，展开抽屉后底栏按钮隐去、抽屉底栏无缝升起唯一主按钮；点击直接平滑滚动回骰碗中心并派发投掷。整个 DOM 树严格保证主动作唯一性，键盘焦点 trap 与 Esc 返回处理严丝合缝，无可挑剔。
3. **独立“我的上一掷”持久化与结果展示阶段（Pacing）**：
