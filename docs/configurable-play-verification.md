## 独立审查发现与复现

主代理的跨层用例位于 `tests/configurable-play.acceptance.test.ts`，通过服务端动作逐份发奖，在每次操作后断言“剩余库存＋已发奖品＝本局初始数量”，没有篡改生产接口或客户端掷骰结果。

| 场景 | 观察与处理 |
| --- | --- |
| 四人当前轮收尾，后两人依次五红、插金花 | 持续版由插金花胜出，锁定版由先五红者胜出；最终唯一得主获得三份状元奖；重复请求不重发 |
| 固定轮数上限与完整发奖同时达到 | 以真实发完结果结算，既不多打一轮，也不误报未发完 |
| 普通奖发空，但连续超过 20 轮没有状元 | 继续至出现状元，再完成当前轮；最后一位仍能顶替 |
| 超时消耗最后一次机会 | 首次复现结算后到期时间为空；已修复，从结算时刻开始保留 24 小时 |
| 最后一位在线玩家离席，剩余玩家只是掉线 | 首次复现没有立即暂停；已修复，操作提交时就暂停并建立离线期限 |
| 固定局最后一轮全员离席 | 首次复现误记为正常结束；已修复，记录全部离席且未完成 |
| V1 房间保存了 pendingFinish，但尚无状元 | 首次复现错误进入收尾；已修复，没有状元时清除旧收尾标记，保留原固定轮数继续 |
| 完成、再开局后重启 | 初稿把新公共归档当内部快照读取，误报损坏；已修复，按归档身份查重并区分新旧格式，增加真实重启回归 |

## 环境说明

使用 Node v24.20.0、本地 SQLite 测试数据库及已安装的 Chromium。真实 HTTP／Socket 测试需要监听回环端口；首次沙箱运行被 `listen EPERM` 拦截，授权后基线测试通过。

开发工作区使用本地复制的依赖，避免借用原目录的依赖缓存造成跨目录写入。测试数据与构建产物不纳入 Git。本轮为本机 Chromium 验证，包含三个视口的布局与实际页面截图；未进行 iOS／Android 真机或公网部署验证。
