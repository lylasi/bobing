# 博饼房规、奖品配置与骰子体验需求

日期：2026-09-26。状态：Q1–Q23 的产品选择已确认；本文件为最后一次整体共识评审稿，尚未开始实现。

本文件记录本次访谈的最终选择。与旧版 product-spec.md、rules-research.md、ui-brief.md 冲突时，以本文件和用户后续指示为准。旧文档中“固定轮数”“禁止自定义规则选择器”“音效不作为依赖”等限制不再阻止本次修改。

## 1. 交付目标与分工

- 默认采用“持续顶状元＋奖品发完结束”，不设轮数上限，正常结束必须包含状元奖。
- 支持开发者维护的系统房规，以及保存在本机浏览器的个人奖品方案。
- 添加本人掷骰音效开关，改善现有画风中的骰子运动。
- DeepSeek Harness 负责共享契约、规则、状态机、服务端、持久化和业务测试；Pi 负责页面、交互、浏览器个人方案、音效、动画和 UI 测试。主代理负责契约评审、集成及验收。
- 委派一律使用 codeg-mcp 的 delegate_to_agent，agent_type 分别为 deepseek、pi；不替换为其他代理或原生子代理。

## 2. 系统房规与结束方式分开选择

### 2.1 两种系统房规

| 系统房规 | 状元规则 | 默认性 |
| --- | --- | --- |
| 持续顶状元 | 收尾结束前，严格更大的状元成绩替换当前领先者；同分保留先博得者 | 默认 |
| 高阶锁定 | 首次出现五红、六黑、遍地锦、六红或插金花即锁定唯一得主；后续更大牌型也不能顶替。四红、五子登科阶段仍允许争夺 | 可选 |

“锁定”只确定状元得主，不让整局提前结束。两种房规均只有一位状元，最终获得状元档配置的全部份数。被顶替的是暂定状元归属；普通奖不追回。

系统方案使用行为名称，不标榜为唯一地域标准。系统方案由开发者维护，玩家只能选择，不能修改判奖逻辑。本轮不做管理员账号或通用规则编辑后台。

### 2.2 共同判奖规则

- 保留 V1 的牌型判定和排序：插金花 > 六红 > 遍地锦 > 六黑 > 五红 > 五子登科 > 四红状元 > 对堂 > 三红 > 四进 > 二举 > 一秀。
- 遍地锦是六个一点；这里的六黑是六个相同的二、三、五或六点。
- 五子登科先比五颗相同骰子的点数，再比剩余一颗；四红比较另外两颗之和；五红比较另外一颗。
- 同分先到先得，不加赛。
- 一次掷骰只判最高牌型；四进不兼得一秀或二举，插金花不额外领取对堂。
- 六红不清空普通奖池，不追回其他人的普通奖。
- 某档库存已空时照常记录命中的牌型，但不发奖、不降级、不补发。
- 现有六颗六面骰子、服务端随机数和原有判奖样例继续有效。

### 2.3 两种结束方式

| 结束方式 | 行为 |
| --- | --- |
| 奖品发完结束 | 默认；没有轮数上限。五档普通奖库存全为零，且已存在状元候选或锁定得主，才进入本轮收尾 |
| 固定轮数 | 保留每人 5／10／20 轮的选择；达到上限后结算，即使奖品未发完或状元空缺，也明确显示达到轮数上限 |

奖品发完的收尾规则：完成当前整轮，不额外增加一整轮。尚未轮到的在席玩家仍有本轮机会；持续顶状元版仍能改变领先者，锁定版不能改变已锁定得主。收尾结束时一次性发放全部状元份数。

“普通奖全空但没有状元”不能触发奖品发完结束，继续轮转至出现状元；固定轮数方式仍受其明确选择的轮数上限约束。不能用状元库存已归零作为进入结算的前提，因为状元实际发放发生在结算时。

固定轮数方式也允许在具备完整发奖条件后按当前轮收尾；同时到达轮数上限时，结束原因必须与实际剩余奖品一致，不把未发完描述成奖品发完。

## 3. 奖品配置与个人方案

- 六档名称固定：状元、对堂、三红、四进、二举、一秀。
- 默认份数依次为 1／2／4／8／16／32，共 63 份；默认值可恢复。
- 每档数量均为至少 1 的整数，不允许设 0，也不允许只保留状元；合计不要求为 63。
- 状元数量表示同一位胜者获得的份数，不表示多个状元名额。
- 每档有一条可选奖品内容文字，例如“月饼一盒”；不填写则不显示内容栏，不改变档位名称。
- 内容为展示文字，不新增支付、积分算法、实物履约或图片上传。
- 个人方案支持命名保存、选择应用、更新和删除，保存数量、奖品内容与结束方式；系统房规在房间配置中单独选择，个人方案不能携带自定义判奖代码或锁定阈值。
- 个人方案只存当前浏览器，界面说明换浏览器或清除站点数据后不可恢复；存储不可用时仍可临时配置开房，不假报已持久保存。
- 选择个人方案后可继续微调。修改个人方案不改变已创建或已开始房间的配置。

## 4. 创建、等待与配置冻结

- 创建时选择系统房规、结束方式、各档数量及可选内容；默认系统房规为持续顶状元，默认结束方式为奖品发完结束。
- 房主在等待室可修改上述配置。其他玩家可以查看完整配置，不能修改。
- 配置发生实际变化后，其他未离席玩家的准备状态取消，需要重新准备；房主保留原来的准备状态。保存失败保持原配置，不局部生效。
- 已开始的对局不能修改配置。服务端保存本局配置和规则版本快照，不能随系统预设或浏览器模板更新而变化。
- 再开一局沿用本房间选择的系统房规、奖品配置与结束方式；重置库存、状元、锁定状态、累计统计与记录，回等待室后可以再修改。
- 原有至少两位在线且准备好才能开局、人数上限、30 秒机会、幂等投掷、房主转交、开局后不加入新玩家继续适用。

## 5. 中止、离席、离线与过期

- 房主仍可明确主动中止，操作前保留现有二次确认。结果显示“房主中止”，展示已发奖品和剩余奖品；中止时已有状元按现有提前结算行为发给当时得主，没有则显示空缺。
- 开局后只剩一位未离席成员时继续轮转，不再因少于两人自动结束。主动离席与暂时掉线仍有区别；离席者历史和已得奖项保留。
- 沿用现有状元资格：离席不清除已经取得的状元成绩或锁定资格；最终仍可归原得主。暂时离线同样不会自动让出状元。
- 全员主动离席时按未完成关闭并保存记录，不制造一场“奖品发完”的结果。
- 全员离线时暂停当前机会，保存剩余时间。暂停不消耗机会、不产生随机骰子，也不发奖。
- 活跃对局不受从创建起计算的 24 小时固定期限截断。
- 从全员离线的时刻起保留 24 小时。有人重连则取消该次到期计时，恢复剩余回合时间；以后再次全员离线，则开始新的 24 小时计时。
- 服务重启必须保留已存的离线起点与到期时间，不能每次加载都顺延 24 小时。
- 到期仍无人回来时，保存实际已发奖记录与“离线过期、未完成”标记，再使房间过期；不把未结算的状元或剩余普通奖自动记为已发。
- 过期归档不能被删除房间时的级联清理一起删除。原有过期页面仍明确提示不能续局，本轮不增加跨房间历史中心。
- 等待、完成或关闭状态沿用有期限的房间清理；长局完成或回等待室时，从此次状态转换起计算 24 小时，确保能查看结果或再开局。

## 6. 音效与动画

- 音效首次默认关闭；开关只影响本人并保存在本机浏览器。
- 只为本人新发起的掷骰播放骰子翻滚、碰撞、落碗音效；别人掷骰直接显示结果，不播放掷骰动画或音效。
- 沿用现有画风，六颗骰子有不同的翻滚、位移、碰撞节奏并逐颗停稳；不引入完整 3D 物理场景。
- 最终六颗点数必须完全来自服务端；中间动画随机帧不得用于判奖或库存计算。
- 刷新、重连、历史快照及重复响应不重播旧动画或旧音效。失败时不显示伪造的中奖结果，不无限播放声音。
- 尊重 prefers-reduced-motion，保留键盘操作、可访问名称和最终结果播报。
- 375／768／1440 像素布局可用，375 像素无横向溢出，主要点击目标至少 44 像素。

## 7. 页面展示与数据一致性

- 首页、邀请概况、等待室、游戏区、房间规则、结算页显示本房间真实系统房规、结束方式和奖品配置。
- 无限轮数显示“第 N 轮”以及剩余奖品，不出现伪造的总轮数分母。
- 奖池进度分母来自本局初始配置；奖品名称和可选内容按本局快照展示，不继续写死 63 份。
- 状元展示区分“当前领先、仍可被顶替”“已锁定”“最终状元”；锁定只说明得主确定，不暗示整局完成。
- incomplete 表示主动中止、全部离席关闭或离线过期导致未完成；固定轮数按所选上限正常结束不属于未完成，未发奖品通过剩余库存单独展示。
- 较大的状态更新不能被旧快照覆盖。服务端仍是判奖、库存、权限、轮次、结束与结算的唯一权威。
- 无限轮数可能超过现有 240 条记录窗口，实际投掷、超时和已发奖累计统计不能由截断后的记录数组倒算。近期记录窗口与完整累计统计分开保存，界面明确窗口含义。
- 已持久化的旧房间补齐新配置：原 maxRounds 保留为固定轮数、V1 映射为持续顶状元、初始数量使用原默认值、奖品内容为空。不能把旧固定轮数房间静默切为无限轮数。
- 凭证或凭证哈希不能进入公共配置、快照、邀请、日志或浏览器模板。

## 8. 验收场景

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| A01 | 使用默认配置新建房间 | 持续顶状元＋奖品发完结束；默认六档共 63 份 |
| A02 | 超过 20 轮仍有普通奖 | 无限轮数局继续，不被旧上限结束 |
| A03 | 普通奖全发完但没有状元 | 继续投掷；出现状元后完成当前轮，再发状元奖 |
| A04 | 当前轮第三人领走最后普通奖，第四人掷出更大状元 | 持续版可顶替；本轮结束结算，不多打一轮 |
| A05 | 锁定版先五红、后六红或插金花 | 状元仍归先五红者，普通奖尚未发完时游戏继续 |
| A06 | 锁定版先四红、后五子，再出现六黑 | 前两次可争夺，六黑出现后锁定 |
| A07 | 状元配置 3 份 | 唯一最终状元获得 3 份，重复结算不再次发放 |
| A08 | 任一档 0、负数、小数或缺失 | 服务端拒绝非法配置；合法数量及内容保存后各端一致 |
| A09 | 内容留空、填写以及修改数量 | 留空不显示内容；已填内容正确显示；分母和总数随本局配置变化 |
| A10 | 等待室改配置、非房主改配置、开局后改配置 | 有权限的等待室修改原子生效并取消其他玩家准备；另外两种拒绝 |
| A11 | 再开局与修改浏览器模板 | 再开局沿用房间配置但清空本局状态；模板变化不污染房间 |
| A12 | 全员离线、重连、再次离线、服务重启 | 倒计时暂停恢复正确；24 小时离线期限取消和重建正确，重启不无限续期 |
| A13 | 连续活跃超过创建后 24 小时；离线超过 24 小时 | 前者继续；后者过期并保留标为未完成的已发奖记录 |
| A14 | 对局中仅一位成员仍在席 | 可以继续投掷，不能因人数少于两人被自动结束 |
| A15 | 固定 5 轮，奖品未发完 | 达到上限后明确按轮数结算，剩余奖品和空缺情况可见 |
| A16 | 连续处理超过 240 个机会 | 累计投掷／超时／获奖统计准确，不随历史窗口裁剪减少 |
| A17 | 首次使用、打开音效、刷新、另一个玩家投掷 | 首次静音，设置可记住，本人新投掷才发声，旧记录和他人投掷无声 |
| A18 | 普通投掷、网络失败、重复响应、减少动态效果 | 点数可信、动效能结束、无旧记录重播，减少动态效果有效 |
| A19 | 不兼得与普通奖不追缴 | 四进和插金花只按原 V1 发奖；六红不夺走普通奖 |
| A20 | 同分状元；五子不同点数组合；旧房间恢复 | 同分先到先得、五子比较沿用 V1，旧房间配置正确恢复 |

## 9. 实施顺序

1. DeepSeek 先落实共享契约和系统方案注册表，主代理核对本规格。
2. 契约固定后，DeepSeek 开发服务端业务和持久化；Pi 按同一契约开发 UI、个人模板、音效与动画。
3. 主代理检查端到端路径和多人一致性，发现的问题交回对应负责人修复。
4. 通过类型检查、业务测试、构建和相关浏览器验收后交付。当前阶段仅形成规格和计划，不启动业务实现或发布。

## 10. 前后端契约草案

本节供开发者衔接，普通玩家页面不展示字段名。DeepSeek 首先把以下名字落实到共享类型；主代理确认契约后通知 Pi 使用同一版本。实现期间若需要改名，必须同时修订本节并通知另一方。

~~~ts
// shared/types.ts：新增／扩展类型；既有 PrizeKey、ResultCode、DiceResult 保留。
export type RulesetId = 'continuous' | 'high-tier-lock';
export type EndCondition =
  | { mode: 'all-prizes' }
  | { mode: 'rounds'; maxRounds: 5 | 10 | 20 };
export type PrizeConfig = Record<PrizeKey, { count: number; content: string }>;
export interface RoomConfig {
  rulesetId: RulesetId;
  endCondition: EndCondition;
  prizes: PrizeConfig;
}
export interface RulesetSnapshot {
  id: RulesetId;
  version: 1;
  name: string;
  diceRulesVersion: 'unified-v1';
  championPolicy: 'competitive' | 'lock-high-tier';
  lockCodes: readonly ResultCode[];
}

// RoomState 增加以下字段；原顶层 maxRounds 改为从 config 派生，不再双写。
// rulesVersion 可保留为基础判奖版本，但 UI 规则名称必须读取 ruleset.name。
// config: RoomConfig
// ruleset: RulesetSnapshot
// initialPool: Record<PrizeKey, number>
// closingRound: number | null
// incomplete: boolean
// allOfflineSince: number | null
// expiresAt: number | null   （替换原来的 number；活跃对局为 null）
// Champion 增加 locked: boolean、lockedBy: ResultCode | null。
// Player 增加 rollCount: number、timeoutCount: number。
// FinishedReason 保留旧值以读取旧归档，新增 'offline-expired'、'all-left'。

// 创建请求：新客户端发送 config；旧客户端 maxRounds 请求由服务器显式适配。
export interface CreateRoomRequest {
  nickname: string;
  name: string;
  maxPlayers: number;
  config?: RoomConfig;
  maxRounds?: 5 | 10 | 20;
}
// config 与旧 maxRounds 同时出现时拒绝，避免两套结束规则冲突。
// Action 增加 { type: 'update-config'; config: RoomConfig }。
// RoomPreview 包含 config、ruleset、expiresAt，仍不含成员信息和凭证。

// shared/room-config.ts：DeepSeek 实现、双方共同导入。
export function createDefaultRoomConfig(): RoomConfig;

// shared/rulesets.ts：DeepSeek 实现，预设记录只读，返回的房间快照必须深拷贝。
~~~

近期记录继续限制为 240 条，累计统计独立保存。规则说明、初始数量、锁定状态、收尾状态、统计和过期时间均从服务端公共快照读取。个人模板只保留 RoomConfig 中的 prizes 与 endCondition，不保留可编辑的 RulesetSnapshot。
