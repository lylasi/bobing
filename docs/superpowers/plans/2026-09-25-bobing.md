# 月满博饼 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.
> 本项目的用户明确指定了代理分工：所有委派必须通过codeg-mcp `delegate_to_agent`，界面交Pi（`pi`），应用代码交DeepSeek Harness（`deepseek`）。该明确指示优先于技能中的默认子代理或执行方式。主代理负责需求、规则、审查和验收。

**Goal:** 交付可以创建房间、分享邀请、实时多人博饼并持久化恢复的中文网页。

**Architecture:** React前端通过REST发送操作，通过Socket.IO接收带revision的完整房间快照。单实例Node后端掌管身份、随机骰子、回合和判奖，以SQLite事务保存状态和幂等回执；纯规则与游戏状态函数独立可测。

**Tech Stack:** Node.js >=24.0.0、npm、TypeScript、React、Vite、Express、Socket.IO、node:sqlite、Vitest、Playwright、Docker。

**Spec:** [完整需求](../../product-spec.md)、[规则与来源](../../rules-research.md)、[Pi界面需求](../../ui-brief.md)。

## Global Constraints

- Node.js >=24.0.0；React + TypeScript + Vite；Express + Socket.IO；SQLite使用`node:sqlite`；npm作为包管理器。
- 用户界面与错误提示为简体中文；所有按钮、输入框具有可访问名称；不把框架名、数据库名等实现细节放到普通玩家流程。
- 支持375px、768px、1440px布局；375px不得横向滚动；主要点击目标>=44px。
- 服务端是随机数、轮次、权限、奖池、判奖、结算的唯一权威，客户端不得提交骰子点数或中奖等级。
- 第一版只部署一个Node实例；SQLite持久化目录必须挂载；禁止用多副本启动该版本。
- 应用前后端同源；开发通过Vite代理`/api`与`/socket.io`。生产Express提供构建后的静态文件和SPA路由回退。
- 房间与邀请不含账号个人资料，只有用户输入的昵称和房名。
