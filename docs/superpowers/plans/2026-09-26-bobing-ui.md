# 博饼房规配置与骰子体验 UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **用户指定的执行方式优先：**本计划由 codeg-mcp delegate_to_agent 的 pi 执行，业务与共享契约由 deepseek 执行。整体需求确认前只评审计划，不实现。当前目录没有 Git 仓库，不初始化仓库、不执行 git commit。

**Goal:** 让玩家能配置和保存奖品方案、看懂本局房规，并体验可关闭的本人骰声与更丰富的骰子动画。

**Architecture:** 创建页与等待室复用同一个配置表单，房间展示读取服务端配置快照。个人模板和音效设置保存在浏览器；动画只消费服务端结果，不参与判奖。

**Tech Stack:** React 19、TypeScript、Vite、CSS、Web Audio API、Vitest、Playwright。

**Spec:** ../specs/2026-09-26-bobing-configurable-play.md；配套业务计划为 2026-09-26-bobing-business.md。

## Global Constraints

- 默认采用“持续顶状元＋奖品发完结束”，不设轮数上限，正常结束必须包含状元奖。
- 六档名称固定，数量至少 1；内容是可选文字，留空则不显示。
- 个人方案只保存数量、奖品内容和结束方式，系统房规另行选择。
- 音效首次默认关闭；开关只影响本人并保存在本机浏览器。
- 别人掷骰直接显示结果，不播放掷骰动画或音效。
- 最终六颗点数必须完全来自服务端；刷新、重连和重复响应不重播旧事件。
- 尊重 prefers-reduced-motion；支持 375／768／1440 像素布局，375 像素无横向溢出，主要点击目标至少 44 像素。
- 用户界面使用简体中文，不显示 DTO、SQLite、Web Audio 等实现名词。
- 本轮不增加图片上传、完整 3D 物理场景、背景音乐、其他玩家动画开关或管理员后台。

- [ ] **Step 3: 接入新建和等待室。**

Home 用 useState(createDefaultRoomConfig) 初始化，提交 config，移除旧顶层 maxRounds。WaitingRoom 仅房主看到“修改房规与奖品”，用现有 Dialog 打开同一编辑器。WaitingRoomProps 增加 onUpdateConfig: (config: RoomConfig) => Promise<ActionOutcome>，ActionOutcome 直接导入现有 src/hooks/useRoom.ts；Room 页面传入 config => runAction({ type: 'update-config', config })。编辑器保存时检查实际结果，不能把 Promise 正常返回当成操作成功：

~~~tsx
const [configOpen, setConfigOpen] = useState(false);
const [configError, setConfigError] = useState<string | null>(null);
// 下列代码位于等待室编辑器的异步提交事件中，draft 是本地配置草稿。
const outcome = await onUpdateConfig(draft);
if (outcome.ok) {
  setConfigError(null);
  setConfigOpen(false);
} else {
  setConfigError(outcome.error?.message ?? '配置保存失败，请重试');
}
~~~

动作成功以服务端新快照为准。弹层内显示“修改后，其他玩家需要重新准备”。presence 广播不能把玩家正在编辑的草稿重置；只在打开编辑器或成功保存后重新取配置。服务端拒绝时保留草稿并在弹层内显示 configError。

## Task 3: 本人音效和分阶段骰子动画

**Files:** src/lib/dice-sound.ts、src/hooks/useSoundSettings.ts、src/hooks/useDiceAnimation.ts、src/components/GameBoard.tsx、Bowl.tsx、Dice.tsx、src/styles.css、tests/e2e/dice.spec.ts。

**Interfaces:** 保留 useDiceAnimation 的现有三个输入；DiceAnimationState 增加 phase 与 settledCount：

~~~ts
export type DicePhase = 'idle' | 'tumbling' | 'landing' | 'colliding' | 'settling';
// 既有 dice、spinning、revealed 保留，新增 phase: DicePhase、settledCount: number。
export interface DiceSoundController {
  unlock(): Promise<void>;
  start(): void;
  impact(intensity?: number): void;
  stop(): void;
  dispose(): void;
}
export function createDiceSound(): DiceSoundController;
export function useSoundSettings(): {
  enabled: boolean;
  setEnabled: (enabled: boolean) => void;
};
~~~

- [ ] **Step 1: 添加音效开关与回归观察。**

使用存储键 bobing.sound-enabled.v1，缺失或异常均默认 false。按钮可访问名称为“开启音效”或“关闭音效”，aria-pressed 与 enabled 一致。按钮放在骰子区或现有工具区，保留至少 44 像素点击目标，并验证手机首屏布局。

通过浏览器测试覆盖首次静音、切换后刷新保留、localStorage 不可用仍可临时切换。测试可在 addInitScript 中观测 Web Audio 启动次数与动画状态变化，不在生产应用增加测试上报接口。

- [ ] **Step 2: 实现可停止的本地骰声。**

通过 Web Audio 短噪声与增益包络合成滚动、碰撞和落碗声，不增加外部音频资源或背景音乐。AudioContext 在用户点击开启或掷骰的手势中解锁；解锁失败不能阻塞掷骰请求。start、impact、stop、dispose 均能安全重复调用；静音、失败、路由离开和卸载时清理正在发声的节点和计时器。

设置初始化必须容忍隐私模式：

~~~ts
export function readSoundEnabled(): boolean {
  try {
    return globalThis.localStorage.getItem('bobing.sound-enabled.v1') === 'true';
  } catch {
    return false;
  }
}
~~~

只在本机新发起的本人掷骰事件中 start；收到历史快照、其他人的结果或重复 revision 不发声。动画与声音均不改变骰子结果、回合 deadline 或奖池。

- [ ] **Step 3: 改进动画的事件识别和阶段控制。**

继续使用 gameNumber＋记录 ID 识别新权威结果，不依赖完整快照对象身份。首次载入先消费现有记录，不动画；通过 rollPending 的新请求边沿给本机投掷授权动画，避免刷新自己最后一手也重播。实际结果到达后，未停稳骰子显示装饰帧，已停稳骰子逐颗固定为该条服务端点数。

阶段依次为 tumbling→landing→colliding→settling→idle，settledCount 从 0 到 6。新一手权威结果取代旧事件时取消旧定时器；别人掷骰直接显示最新六个点数并停止旧装饰效果。失败时恢复最后一手权威结果；再开局清空；超时记录不生成骰子。

- [ ] **Step 4: 增加 CSS 运动层次，保留真实点阵结构。**

Bowl 给六个槽位设置不同 --die-index 和状态 class／data 属性；保留 .bowl .dice .dice-pip--on 结构。可使用如下起始轨迹，再依据三个宽度截图调整幅度与停稳节奏：

~~~css
@keyframes dice-tumble {
  0% { transform: translate(-12px, -24px) rotate(-24deg) scale(.94); }
  45% { transform: translate(10px, 5px) rotate(18deg) scale(1); }
  75% { transform: translate(-5px, -7px) rotate(-9deg); }
  100% { transform: translate(0, 0) rotate(0deg); }
}
.bowl[data-phase='tumbling'] .bowl-slot {
  animation: dice-tumble 480ms ease-in-out infinite;
  animation-delay: calc(var(--die-index) * -47ms);
}
@media (prefers-reduced-motion: reduce) {
  .bowl .bowl-slot { animation: none; transition: none; }
}
~~~

landing、colliding 和逐颗 settling 必须有实际不同的运动阶段，不能只为相同晃动换名字。控制位移不出碗、不遮挡必要按钮；中间帧继续隐藏于辅助技术，停稳后播报真实结果。减少动态效果时直接显示权威结果，不等待装饰性计时结束。

- [ ] **Step 5: 验证真实多端与错误路径。**

扩展既有 dice.spec.ts：本人动画终点与真实记录的六个点阵相等；别人一端立即显示同一结果；已开启音效时仅本人新动作创建发声节点；重复快照、刷新和重连的观测计数不增加。观察器必须记录整个加载期间的变化，不能只等待 900ms 后断言没有动画而漏掉旧记录重播。

继续覆盖请求失败、延迟响应、新事件到达、再开局、减少动态效果。调用现有 expectBowlMatchesLatestRecord 验证实际 DOM 点阵，不只验证文字或“动画已结束”标志。网络异常测试不得伪造获奖结果。此任务覆盖 A17–A18。
