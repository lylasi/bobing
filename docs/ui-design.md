# 月满博饼 · 界面设计规范与 2026-09-27 架构增补

## 0. 2026-09-27 最新设计演进增补（当前实现规范）

本节汇总 2026 年 9 月 27 日由 Pi 视觉与交互工作流完成的增量设计与实现规范。当前本地代码已完成实现（local code implemented），未提交、未推送、未部署（no commit, no push, no deploy）。最终集成验证与测试结果以根工作流的 [docs/verification-2026-09-27.md](verification-2026-09-27.md) 为准（本文档不硬编码临时测试状态）。本节涵盖游戏对局区增强、移动端底部固定活动栏与半屏抽屉、个人奖品权威历程、六档奖品单层编辑排版、游戏大厅与真实实时旁观室。

### 0.1 移动端底部固定活动栏与“最近 10 次”半屏抽屉（RecentActivity）
- **常驻底栏（`.action-bar`）**：
  - 手机端首屏单行展示最新 1 条权威投掷摘要（例如：`最近：阿月（我） · 一秀`）与“最近 10 次 ↑”入口；
  - 唯一移动端主掷骰按钮（“掷出好运”，高 52px、圆角 26px）常驻底栏；全页面任意时刻移动端可见掷骰按钮严格仅有 1 个；
  - 通过 `ResizeObserver` 实测底栏渲染高度并写入 `--mobile-dock-height`（默认兜底 84px），页面容器 `.room-main` 基于此变量与 `env(safe-area-inset-bottom)` 动态计算底部避让留白，杜绝遮挡与滚动冲突。
- **半屏抽屉（`.recent-drawer`）**：
  - 点击“最近 10 次 ↑”展开半屏抽屉，支持“全桌最近 10 次”与“只看我”快捷过滤切换；
  - 抽屉展开时，主掷骰按钮移入抽屉底部，点击立即收起抽屉并触发投掷；
  - 抽屉内置单条骰面展开/收起（`.recent-item-dice-toggle`，点击区 ≥36px）；
  - 用户向下滚动阅读旧记录时，新投掷到达不强拉回顶部，显现“↑ 有新记录”浮动气泡；
  - 严格支持 Escape 键关闭与焦点还原至入口触发按钮。

### 0.2 紧凑型房间顶栏与“更多”面板（Compact RoomHeader & More Panel）
- **单行常驻顶栏（`.room-header--compact`）**：
  - 对局开启后收拢为单行，仅展示房间名（16–18px）、局数徽章、在线旁观人数、连接状态与“更多 ⋯”次按钮；
  - 移除首屏冗余的“结果停留 N 秒”常驻标签，收紧移动端首屏高度预算；
  - 旁观人数（`viewerCount`）在顶栏常驻可见。
- **“更多”展开面板（`.room-more-panel`）**：
  - 房码、席位数、旁观开关状态、规则集、停留秒数等信息统一收纳至面板内部；
  - 房主提前结束对局等高危次操作置于面板内，避免首屏误触。

### 0.3 席位条、个人权威结果与状元历程（SeatStrip, MyRewards & ChampionHistory）
- **常驻席位条（`.seat-strip`）**：
  - 居于对局区顶部，紧凑统计在玩/在线/旁观人数，头像列表（`.seat-chip`）在内部横向平滑滚动，绝不引发全页水平溢出；
  - 突出“我”、当前轮次带骰子高亮指示及离线置灰态。
- **状元简栏与模态历程（ChampionHistory）**：
  - 简栏单行展示当前领先状元、牌型、锁定状态与奖品摘要，轻触“历程 ›”唤起完整模态；
  - 桌面端右栏卡片呈现专属红金横幅、历次易主（first / takeover / improved / locked / settled）时间轴与各次骰面。
- **我的奖品与个人状元经历（MyRewards）**：
  - **移动端内联条（`.my-rewards-inline`）**：常驻骰碗下方，权威展示“我的上一掷”结果（服务端独立记录，不受全桌裁剪或覆盖）、被超提醒、已落袋普通奖份数及“我的奖品 ›”弹窗入口；
  - **奖品文案完整换行**：`.my-prize-content` 彻底放弃 ellipsis 截断，支持长奖品文案（如“中秋团圆限定茶点与月饼组合礼盒”）完整多行换行；
  - **状元行状态独立行**：`.my-prize-row--champion` 采用换行流（`flex-wrap: wrap`），将超长状态文案（如“当前领先（终局结算后可获 1 份，暂不计入已获份数）”）置于独立换行行，杜绝挤压奖品名称为单字竖列；
  - **桌面端首屏优先排版**：左栏使用 CSS `order: -1` 将个人奖品卡片置于玩家列表之前，配合玩家列表自身 `max-height: 380px` 内部滚动，确保 12 人对局时个人权威结果第一屏随时可见。

### 0.4 单层六档奖品手机排版（Six-Tier Prize Config Editor）
- 房间配置与设置弹窗中的六档奖品表单在手机视口（≤600px）采用明确的 `'tier count' / 'content content'` 结构：
  - **第一行**：左侧奖级名称与份数描述、右侧为数量输入框（触控区 ≥42px，靠右对齐）；
  - **第二行**：奖品内容输入框独占全宽（100%），彻底解决 320px 超窄视口下内容框宽度局促问题。

### 0.5 游戏大厅（/lobby）与真实实时旁观室（/room/:code/watch）
- **游戏大厅（`.lobby-main`）**：提供公开对局列表检索、按游戏状态（等待中/博饼中/已结束）筛选与房间码快速直达；单卡片在 320/375 采用竖向自适应折行。
- **实时旁观室（`SpectatorRoom`）**：旁观者通过 WebSocket 接收全实时广播与骰子三维动画；隐藏所有投掷、准备与个人结算交互部件；顶部展示“旁观中”金棕徽章，底部不渲染操作底栏。

### 0.6 视口几何预算与导航规范（Mobile Geometry & Navigation）
- **单行顶栏（SiteHeader）**：在 320px 与 375px 超窄屏幕下强制单行排版（`flex-wrap: nowrap`），“游戏大厅”与“博饼怎么玩”链接保持 ≥44px 触控热区与文字清晰可读，不引发整页水平溢出。

  - **首屏露底与真实可视净空**：个人战绩条底边（667.344px）在底栏顶边（701px）上方露出的真实可视净空间距约为 **33.7px**（701 - 667.344 ≈ 33.656px ~ 33.7px），首屏不滚动能够完整露底，**并非此前估算的 >100px 裕量**；

- **多人与长文案核验（根工作流实测确认）**：
  - 根工作流独立 12 人浏览器测试脚本在 320 / 375 / 768 / 1440 视口下通过 7 组检查；

不远程加载字体。标题用宋体700，正文系统无衬线400/500。数字使用tabular-nums。正文16px/1.65，辅助信息14px/1.5，表单label14px/600，移动标题36px/1.3，桌面主标题60px/1.25，房码24px并适当字距。

主代理实算对比度：ink/paper=13.50:1，红/白=4.93:1，secondary/paper=6.55:1。`decorative-muted`仅3.25:1，只用于装饰或禁用态，正常小字用secondary；gold/paper仅2.12:1，金色不能单独作重要文字或焦点环。焦点采用2px ink轮廓与2px白色间隔。

页面顶部可用小印章品牌、轻量月相/桂枝线稿、细线分隔和“中秋欢聚”眉题。保留大面积呼吸感。瓷碗主体用CSS径向渐变+椭圆阴影或内联SVG，避免照片/外链素材；骰子为真实3×3点阵，一/四红色、其余深褐。

## 3. 页面实现规格

### 首页

顶部左侧“月满博饼”与方形红印，右侧“博饼怎么玩”。眉题“中秋欢聚 · 好彩头”，标题“一碗骰声，满桌团圆。”，副标题“开一桌中秋好彩头，邀三五好友一起博个状元。”。瓷碗周边小字“六骰一掷，好运满桌”。

表单卡：“创建房间 / 加入房间”Tab。创建默认展示昵称、房间名称、人数上限、系统房规（默认“持续顶状元”，可选“高阶锁定”）、结束方式（默认“奖品发完结束”，可选“固定轮数”5/10/20轮）、简洁默认奖品数量摘要（默认共 63 份：`状元 1 · 对堂 2 · 三红 4 · 四进 8 · 二举 16 · 一秀 32`，并随当前草稿实时更新）与“调整奖品与个人方案”展开按钮（`aria-expanded` + `aria-controls`，首页默认收起 `false`，点击目标 `>= 44px`），紧随其后即为主按钮“创建房间”，使 1440 桌面无需滚动即可看到“创建房间”按钮（`top Y = 767px`，底边 `819px < 900px`）、375 手机“创建房间”按钮 `Y = 1385px`（较展开前 `3804px` 缩短 `2419px`）、首页默认总高度 `2411px`（较展开前 `5066px` 缩短 `2655px`）。展开“调整奖品与个人方案”后可编辑六档奖品数量（至少 1 份整数，支持一键恢复默认 1/2/4/8/16/32 共 63 份）、每档可选奖品内容文字（留空不显示说明节点）及本机浏览器个人方案（命名保存、载入、更新、删除，仅保存奖品数量、内容和结束方式，不覆盖当前系统房规）；非法数量草稿即使收起高级区也继续显示 `role="alert"` 错误并禁用提交。等待室房主点击“修改房规与奖品”弹窗则默认展开全部编辑字段（`defaultAdvancedOpen=true`），无需多点一层。加入有 6 位房间码和昵称，主按钮“加入房间”。辅助说明“无需注册，输入昵称即可入席”。底部三个步骤与 6 奖项速览与当前创建配置草稿保持同步，不写死 63 份，也不出现假的在线人数。

### 邀请落地与等待

邀请落地卡显示真实房间名、人数、本房间真实结束方式、系统房规（`ruleset.name`）及本局奖品配置（含非空奖品内容）、昵称、加入按钮。满员：“这桌已经坐满啦”；已开局：“本局已经开始，暂时不能加入”；过期：“这桌已散席，重新开一桌吧”；不存在：“没找到这个房间，请检查房间码”。

等待室上方房名、局编号、6位房码、音效开关、邀请亲友、规则、离开房间。房主额外显示“修改房规与奖品”按钮，打开配置弹层修改系统房规、结束方式与奖品配置；配置实际变更后取消其他未离席玩家的准备状态（房主保留原准备状态），保存失败时保留草稿并在弹层内报错。成员卡含昵称首字圆形头像、昵称、房主小章、在线点、准备状态。空席位使用虚线框“等一位好友”，不伪造昵称。显示“已入座X/Y”；房主按钮“开始博饼”，成员“准备好了/取消准备”。禁用开始时旁边解释“至少2位玩家在线并准备后才能开始”或“等待X准备”。

### 游戏

上方当前轮次（无限轮数显示“第 N 轮”，固定轮数显示“第 N/M 轮”，触发收尾时显示“本轮收尾”）、当前玩家、剩余秒数；中心瓷碗，结果标题；下方主按钮“掷出好运”。自己回合：“轮到你了，掷出好彩头”；他人回合：“等待【昵称】掷骰”；请求中：“骰落瓷碗，静候佳音…”；超时：“本轮超时，已跳过”；暂停：“等待玩家回来，倒计时已暂停”。

普通奖显示“博得一秀 · 获得1份”；无库存：“博得一秀，奖品已领完”；无奖：“好彩头留在下一掷”；状元候选区分“当前状元，仍可被顶替”、“状元已锁定”（高阶锁定触发后显示锁定牌型说明）与结算页“最终状元”。每位玩家都看到相同骰子和文字结果。

奖池为六行带余量数字（分母来自本局 `initialPool`，非空时显示 `config.prizes[key].content`），状元领先者单独金底卡；记录以昵称、点阵、牌型、实际发奖为一行，超时没有骰子，明确说明仅显示最近 240 条记录。房间顶栏提供本人掷骰音效开关（首次默认关闭，保存在 `bobing.sound-enabled.v1`），仅对本人新发起的掷骰合成播放本地 Web Audio 骰声并执行分阶段动画（`tumbling -> landing -> colliding -> settling -> idle`，`settledCount` 从 `0..6` 逐颗停稳）；他人掷骰直接显示最终点数，无动画无声。

### 结算

月金色状元卡：“今宵状元 · 最终状元”（未完成时标记“本局未完成”），展示昵称与实际夺魁骰子（含已离席得主）；无状元则“本局状元空缺 · 好运留待下次”。下方展示结束原因、系统房规、结束方式、各档奖品发放与剩余明细、所有玩家奖项统计及累计实际投掷数（`player.rollCount`）与超时次数（`player.timeoutCount`）。房主主按钮“再开一局”（沿用本房间系统房规、奖品配置与结束方式，重置库存与统计），成员“等待房主再开一局”；离开房间为次按钮。不能简单跳首页却保留用户误以为已离开的在线席位。

### 规则与弹层

规则页：简短三步玩法、按高到低的完整牌型示例、最高单奖/30秒/轮次与来源链接，移动端每牌型一张小行卡。不能直接展示rankKey数组。

邀请弹层最大420px，二维码160–192px，房码、完整可选择链接、复制按钮、系统分享（可用时）。复制成功用status提示“邀请链接已复制”；不支持时保留可选文本并提示“长按或选中链接复制”。

规则弹层最大720px，内部滚动；确认弹层最大400px，简述后果，“继续博饼/确认结束”与“留在房间/确认离开”。Esc关闭、点击遮罩关闭（危险操作仍需点击确认），保持焦点在弹层内，关闭后回到原按钮。

## 4. 状态与可访问性

- 请求失败在相关表单/操作区显示alert；不清空输入；按钮loading含文字；所有点击按钮应使用button而不是div。
- 连接状态文字：连接中、已连接、连接断开，正在重连；离线禁止投掷，不伪造骰子。
- 骰子整体aria-label“骰子，N点”，装饰点隐藏；结果区aria-live=polite，重大错误alert；不对每秒倒计时使用assertive播报。
- Tab有role/aria-selected，输入有label，表单支持Enter；原生button支持Space/Enter。
- 本人新投掷收到结果后的动画约750ms，reduced-motion关闭装饰旋转并直接显示权威结果；全页不能持续闪烁；倒计时<=5秒颜色+文字强调，不只靠颜色。
- Toast不能是获得结果的唯一入口；真实结果留在碗下/记录中。空记录“骰声未起，第一份好运等你开启”。
