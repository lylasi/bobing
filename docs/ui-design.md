# 月满博饼 · 经审查的 Pi 界面规范

来源：Pi通过codeg委派返回的设计，原文见[Pi交付原文](pi-design-response.md)。主代理已按冻结需求修正三处冲突：昵称为1–12字；超时跳过而非代掷；状元在结束时发奖而非掷出后立即获得。补充页面/状态仍以[ui-brief](ui-brief.md)与[product-spec](product-spec.md)为准。本文件是DeepSeek前端实现依据。

不远程加载字体。标题用宋体700，正文系统无衬线400/500。数字使用tabular-nums。正文16px/1.65，辅助信息14px/1.5，表单label14px/600，移动标题36px/1.3，桌面主标题60px/1.25，房码24px并适当字距。

主代理实算对比度：ink/paper=13.50:1，红/白=4.93:1，secondary/paper=6.55:1。`decorative-muted`仅3.25:1，只用于装饰或禁用态，正常小字用secondary；gold/paper仅2.12:1，金色不能单独作重要文字或焦点环。焦点采用2px ink轮廓与2px白色间隔。

页面顶部可用小印章品牌、轻量月相/桂枝线稿、细线分隔和“中秋欢聚”眉题。保留大面积呼吸感。瓷碗主体用CSS径向渐变+椭圆阴影或内联SVG，避免照片/外链素材；骰子为真实3×3点阵，一/四红色、其余深褐。

## 2. 布局（Pi方案与断点补充）

- **1440桌面**：最大容器1200，左右自动留白。游戏三栏280/560/312，间隔24，总宽1200；中心400px瓷碗。首页为左侧文案和主视觉、右侧420px表单卡片的双栏（标题与文案不挤到骰碗中）。顶部导航高80px；底部奖项速览一排6项。
- **768平板**：容器左右24px，首页一列、表单最大560px居中；游戏中心区优先，玩家/奖池在下方并列；完整规则表格改卡片或允许表格自身滚动，不能撑宽全页。
- **375手机**：左右16px，内容343px；标题36px，碗260px，骰子40px。主操作区高76px，底部safe-area；若采用fixed必须给正文相应底部padding。玩家/奖池/记录三个Tab，标题、轮次、倒计时和主操作不藏进Tab。创建页面不固定操作条。
- 主按钮高52px、圆角26px、字18px；移动宽100%，桌面主操作宽240px。次按钮44px、圆角12px。轮数胶囊可视40px但热区>=44px。输入高48px、圆角10px。卡片内边距移动20/桌面24px，圆角16px。
- 骰子桌面52px/圆角10，手机40px/圆角8；规则示例用24px小骰子。6颗在碗内错落摆放，不互相遮住点数；主视觉可以有少量旋转，实际点阵完整可见。

## 3. 页面实现规格

### 首页

顶部左侧“月满博饼”与方形红印，右侧“博饼怎么玩”。眉题“中秋欢聚 · 好彩头”，标题“一碗骰声，满桌团圆。”，副标题“开一桌中秋好彩头，邀三五好友一起博个状元。”。瓷碗周边小字“六骰一掷，好运满桌”。

表单卡：“创建房间 / 加入房间”Tab。创建有昵称、房间名称、人数上限、每人轮数，默认值严格遵照spec；主按钮“创建房间”。加入有6位房间码和昵称，主按钮“加入房间”。辅助说明“无需注册，输入昵称即可入席”。底部三个步骤与6奖项速览使用真实规则，不出现假的在线人数。

### 邀请落地与等待

邀请落地卡显示真实房间名、人数、轮数、“线上统一房规 v1”、昵称、加入按钮。满员：“这桌已经坐满啦”；已开局：“本局已经开始，暂时不能加入”；过期：“这桌已散席，重新开一桌吧”；不存在：“没找到这个房间，请检查房间码”。

等待室上方房名、局编号、6位房码、邀请亲友。成员卡含昵称首字圆形头像、昵称、房主小章、在线点、准备状态。空席位使用虚线框“等一位好友”，不伪造昵称。显示“已入座X/Y”；房主按钮“开始博饼”，成员“准备好了/取消准备”。禁用开始时旁边解释“至少2位玩家在线并准备后才能开始”或“等待X准备”。

### 游戏

上方当前轮X/Y、当前玩家、剩余秒数；中心瓷碗，结果标题；下方主按钮“掷出好运”。自己回合：“轮到你了，掷出好彩头”；他人回合：“等待【昵称】掷骰”；请求中：“骰落瓷碗，静候佳音…”；超时：“本轮超时，已跳过”；暂停：“等待玩家回来，倒计时已暂停”。

普通奖显示“博得一秀 · 获得1份”；无库存：“博得一秀，奖品已领完”；无奖：“好彩头留在下一掷”；状元候选：“博得四红状元 · 当前领先”或“博得四红状元 · 未超过当前领先者”，不假称已领状元奖。每位玩家都看到相同骰子和文字结果。

奖池为六行带余量数字，状元领先者单独金底卡；记录以昵称、点阵、牌型、实际发奖为一行，超时没有骰子。房主结束/离开放右上更多区或底部次要区域，与掷骰保持间距。

### 结算

月金色状元卡：“今宵状元”，展示昵称与实际夺魁骰子；无状元则“本局状元空缺 · 好运留待下次”。下方所有玩家奖项统计、实际投掷数、剩余奖池、结束原因。房主主按钮“再开一局”，成员“等待房主再开一局”；离开房间为次按钮。不能简单跳首页却保留用户误以为已离开的在线席位。

### 规则与弹层

规则页：简短三步玩法、按高到低的完整牌型示例、最高单奖/30秒/轮次与来源链接，移动端每牌型一张小行卡。不能直接展示rankKey数组。

邀请弹层最大420px，二维码160–192px，房码、完整可选择链接、复制按钮、系统分享（可用时）。复制成功用status提示“邀请链接已复制”；不支持时保留可选文本并提示“长按或选中链接复制”。

规则弹层最大720px，内部滚动；确认弹层最大400px，简述后果，“继续博饼/确认结束”与“留在房间/确认离开”。Esc关闭、点击遮罩关闭（危险操作仍需点击确认），保持焦点在弹层内，关闭后回到原按钮。

## 4. 状态与可访问性

- 请求失败在相关表单/操作区显示alert；不清空输入；按钮loading含文字；所有点击按钮应使用button而不是div。
- 连接状态文字：连接中、已连接、连接断开，正在重连；离线禁止投掷，不伪造骰子。
- 骰子整体aria-label“骰子，N点”，装饰点隐藏；结果区aria-live=polite，重大错误alert；不对每秒倒计时使用assertive播报。
- Tab有role/aria-selected，输入有label，表单支持Enter；原生button支持Space/Enter。
- 动画正常900ms，reduced-motion关闭旋转并用<=200ms淡入；全页不能持续闪烁；倒计时<=5秒颜色+文字强调，不只靠颜色。
- Toast不能是获得结果的唯一入口；真实结果留在碗下/记录中。空记录“骰声未起，第一份好运等你开启”。
