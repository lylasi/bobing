# 交付给 Pi 的界面需求

产品名：月满博饼。必须先读[完整需求](product-spec.md)和[规则研究](rules-research.md)。Pi负责设计规范和视觉示范，DeepSeek Harness负责应用代码；不要同时修改应用代码。

## 1. 设计方向

用温暖、有节日气息的现代中式视觉：米白宣纸底、朱砂红主要按钮、深茶色文字、少量月金。避免大面积深色、霓虹渐变或管理后台样式。核心记忆点是一只俯视的红釉/陶瓷碗，放着6颗奶白骰子，旁有月亮、桂枝与小印章。CSS或SVG即可，不依赖付费字体、外链图片或生成图。

主标语“一碗骰声，满桌团圆。”，副文案“开一桌中秋好彩头，邀三五好友一起博个状元。”；清楚告诉用户“创建房间 · 分享邀请 · 轮流博饼”。奖品都是虚拟记录。

## 2. 必须设计的页面

1. 首页：品牌导航、规则入口；标题与瓷碗主视觉；右侧/下方创建卡片（昵称、房名、人数、轮数）和加入房间Tab（房码、昵称）；底部奖项示例与三步流程。
2. 邀请落地页：显示房间真实概况、昵称输入、加入按钮，及满员/已开局/过期三种拒绝状态。
3. 等待房间：房码和邀请；席位、房主、准备和离线徽标；房规摘要；准备/开始按钮及未满足条件原因。
4. 正在对局：桌面中心碗与骰子、左侧玩家、右侧奖池、下方记录；手机优先显示轮次/当前玩家/碗/按钮，再以Tab切换玩家/奖池/记录。房主结束和离开不要紧邻主掷骰按钮。
5. 结算：状元（或空缺）主卡片、玩家奖品明细、剩余奖池、结束原因、房主“再开一局”。
6. 完整规则页、规则弹层、邀请链接/二维码弹层、提前结束/离开确认弹层。

## 3. 状态矩阵

必须写出：默认、hover/focus、提交中、错误、禁用；你自己的回合、其他人的回合、掷骰请求中、900ms掷骰动画、结果无奖、普通奖、状元、中奖但库存用完；连接中、离线重连、全员离线恢复；房间不存在、过期、非法身份、满员；复制成功/复制不可用；成员准备/未准备/房主。

骰面必须有数字语义，如aria-label“骰子，4点”；一点与四点朱砂红，其他点深茶色；用明确几何点阵，不仅放骰子emoji。小图标可用Lucide或内联SVG。所有装饰图片需合适alt或aria-hidden。

## 4. 约束与交付

- 375/768/1440三档布局，主操作触达>=44px；正文>=14px，对比度达到WCAG AA；中式衬线仅用于标题，正文系统无衬线。
- 动态效果尊重reduced-motion；弹窗Esc关闭、焦点管理、Tab顺序、滚动锁定需有说明。
- 房间页面不能用假头像/假在线数据填充；空席位与空记录应有自然的空状态。
- 规则名称固定为“线上统一房规 v1”，不能设计未纳入需求的自定义规则选择器、聊天、积分兑换或支付。
- 写入`docs/ui-design.md`：色彩/字体/间距/圆角/阴影token、各页布局与尺寸、组件定义、所有关键文案、状态变化、移动端适配、交互验收清单。
- 可选写入`design/preview.html`与`design/preview.css`作为纯静态视觉示例，页面中标明“设计示例”。不要修改`src/`、`server/`、`shared/`、package或测试。
- 返回文件路径、设计取舍、DeepSeek能直接照做的注意事项。
